MOBILE-DESIGN.md
Glance Board, seed 105
Brief. An iPhone app for a couple who share one monthly budget. Kind: money. Audience: general. Stack: SwiftUI.
Governing metaphor. In this app, a budget becomes a fuel gauge.
Governing asset. A labelled data curve with a scrub marker.
Display treatment. Bold values with smaller same-baseline unit suffixes.
Restraint rule. Only status colour carries hue, and no row shows two competing figures.
Hero moments. Budget: 1. Scrubbing the curve with a selection tick per data point.
Motion scheme. Standard: critically damped springs everywhere (bounce 0). No overshoot on any flow that moves money, signs or deletes.
Haptic profile. Quiet: system-provided haptics only, plus success and error on committed results.
Not doing. Three refusals: a centred balance over round buttons, cards on every row, status colour used as decoration.
Modules. references/modules/money.md

Write the commitments before any UI code.
SKILL.md

One direction, committed before any UI code

The agent never picks a direction from memory. It writes the commitments in MOBILE-DESIGN.md first, and the gate reads that file.

Four checks before the agent reports. Each one prints what it found.

Gate the result

gate.mjs prints PASS, FAIL or OPEN. OPEN means nothing failed but something went unchecked, and the agent must say what.

Limits, in six questions

It covers user experience, art direction and aesthetic. It does not pick components, state libraries or architecture.

See the source

Has the skill been benchmarked?

No. No benchmark has been run, and nothing here claims it beats anything.

What were the directions studied from?

App Store marketing screenshots, not the apps running. Motion, haptics and sound guidance comes from documentation and text.

How far can the 40 lint rules be trusted?

They are pattern matches. They miss things and sometimes flag fine code.

Does capture work for Android apps?

Not verified. Capture is verified on the iOS simulator. The Android path was written from documentation and has not been run.

Can the review judge motion, haptics or sound?

No. Stills cannot show motion, haptics or sound. The gate says so every time.

Is it affiliated with Taste Skill, Apple or Google?

No, nor with any app in the corpus. No app screenshots are redistributed.

Install and first run, in three steps

1

Add the skill

One command adds it. The repo also installs as a Claude Code plugin, or by git clone and ./install.sh.

Install
$npx skills add https://github.com/therynamo/taste-mobile --skill "taste-mobile"
# or, in Claude Code
/plugin marketplace add therynamo/taste-mobile
/plugin install taste-mobile@taste-mobile
2

Ask for an app

Name the skill in your prompt. The agent reads the brief for kind, audience, platform and stack.

Coding agent
Use taste-mobile. Build an iPhone app for a couple who share one monthly budget.
Brief read: kind money, audience general, platform iOS. Dealing three hands. deal.mjs
Ask for an app
3

Read the report

The agent reports the gate's verdict and names what it could not check.

  • GATE: PASSEverything a script and stills can check was checked
  • GATE: FAILFix and run again, three rounds at most
  • GATE: OPENNothing failed, but something was not checked

Get the skill

Three scripts, zero dependencies. Node 18 or later, plus Xcode's simctl for capture.
